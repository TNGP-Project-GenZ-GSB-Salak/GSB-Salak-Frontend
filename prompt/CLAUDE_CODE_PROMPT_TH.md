# Prompt สำหรับ Claude Code — MyMo Digital Salak + กระปุกออม (Piggy Savings)

## บทนำที่ใช้เป็น task brief (วางให้ Claude Code ทั้งก้อน)

> สร้างแอป React ระดับ production ด้วย **React + Vite** สำหรับฟีเจอร์ "สลากดิจิทัล" ของ MyMo (แอปธนาคารออมสิน) รวมฟีเจอร์ใหม่ "กระปุกออมก่อนซื้อสลาก" (MyPiggy) ที่ให้ผู้ใช้ตั้งเป้าออมเงินก่อนซื้อสลากดิจิทัล พร้อมระบบถอนบางส่วน, เคาท์ดาวน์ซื้ออัตโนมัติเมื่อออมครบเป้า และระบบสะสมตราสัญลักษณ์ (badge)
>
> ตรรกะ interaction/state และหน้าตาทั้งหมดอยู่ใน `prototype-reference.html` (React prototype แบบไฟล์เดียว จบในตัว — **ห้าม ship ไฟล์นี้ ให้ recreate ใหม่**) ส่วน design tokens/components อยู่ใน `design-system/`
>
> ให้สร้างทุกหน้าตามหัวข้อ "หน้าจอ / Screens" ด้านล่าง, ต่อ state transition ตามหัวข้อ "State Management & กฎธุรกิจ" ให้ตรงทุกจุด, ใช้ design tokens (สี, ฟอนต์, spacing) จาก `design-system/tokens/*.css` และ `design-system/styles.css` เท่านั้น **ห้ามคิดค่าสี/spacing เอง**
>
> แบ่ง component ตามหน้า (route) และตาม UI ที่ซ้ำ (ProductCard, LotCard, BadgeChip, ConfirmModal, AmountKeypad, SlideToConfirm) ตามความเหมาะสม แต่ต้องคง**กฎธุรกิจทุกข้อ**ให้ตรงเป๊ะ โดยเฉพาะเงื่อนไขเปิด/ปิดกระปุกออม, พฤติกรรมเคาท์ดาวน์/ซื้ออัตโนมัติ, และการคำนวณหักยอดเงิน — จุดเหล่านี้ถูกแก้บั๊กซ้ำหลายรอบระหว่างรีวิวดีไซน์แล้ว มีโอกาส regress สูงถ้าไม่ระมัดระวัง
>
> ใช้ React Router สำหรับนำทางระหว่างหน้าจอ/สเตป Mock ยอดเงินในบัญชีและข้อมูลสินค้าเป็น local state/fixtures (ไม่มี backend จริง) และทิ้ง TODO ไว้ให้ชัดเจนตรงจุดที่ต้องต่อ API จริง (ยืนยันตัวตน/เลขหลังบัตรประชาชน, ดึงยอดบัญชีจริง, สั่งโอนเงินจริง, ออกเลขสลากจริง)

## ความเที่ยงตรง (Fidelity)
**High-fidelity.** `prototype-reference.html` เป๊ะทั้งสี, ฟอนต์, spacing, และคำ (ภาษาไทย) ให้ recreate โดยใช้ component/token ของ design system แทนการ copy inline style ดิบๆ จาก prototype แต่ค่า spacing/type/color ต้องตรงเป๊ะ

## วิธีอ่านไฟล์ prototype-reference.html
เป็น React component ไฟล์เดียว (custom runtime ไม่ใช่ JSX มาตรฐาน) ใช้ inline style ทั้งหมด การสลับหน้าคุมด้วย `this.state.screen` (string) — หาคำว่า `screen === '...'` และ `isXxx: s.screen === '...'` เพื่อหาเงื่อนไขของแต่ละหน้า แล้วหา `<sc-if value="{{ isXxx }}">` ที่คู่กันเพื่อดู markup ส่วน event handler ทั้งหมดเป็น class method (เช่น `chooseSaveFirst`, `confirmWithdrawFull`, `finalConfirm`) — ให้ยึดจุดนี้เป็นความจริงของ business logic

## หน้าจอ / Screens (ลำดับ flow)

1. **Home** (`screen === 'home'`) — หน้าแรกธนาคาร: header แสดงยอดเงินหลัก (`ยอดเงินหลัก`), กริดเมนูลัด (โอนเงิน, ถอนเงินสด, บิล, **สลากดิจิทัล**, เติมเงิน, ...), แบนเนอร์โปรโมชัน กดปุ่ม "สลากดิจิทัล" → เข้าหน้าสินค้าสลาก
2. **หน้าสินค้าสลาก (Salak home)** (`screen === 'salak'`) — hero การ์ดไล่เฉดส้มแสดงยอดสลากรวม, การ์ดสรุปตราสัญลักษณ์ที่สะสม, แท็บ: **ซื้อสลาก** (รายการซื้อ) / **ข้อมูลผลิตภัณฑ์** / **ประวัติการออก** / **ตั้งค่า** และแท็บย่อย **สลาก (n)** (ล็อตที่ถืออยู่) / **รายการเดินบัญชี** ถ้ามีเป้าออมที่เปิดอยู่ จะมีการ์ดสีชมพู "กำลังออมเพื่อซื้อ {product} {pct}%" กดแล้วไปหน้า Goal Tracker
3. **รายการซื้อสลาก (Buy list)** (`screen === 'buyList'`) — รายการสินค้าสลาก (1 ปี / 2 ปี ฯลฯ) แต่ละอันมี "รายละเอียดเพิ่มเติม" (เปิด sheet) และปุ่ม "ซื้อ" กด "ซื้อ" → เปิด bottom sheet ให้เลือกโหมด: "ซื้อเลย" / "ออมก่อน" / "ยกเลิก"
   - **Modal "มีกระปุกออมที่เปิดอยู่"**: ถ้าผู้ใช้มีเป้าออมเปิดอยู่แล้ว (สินค้าใดก็ได้) แล้วกด "ออมก่อน" อีก ให้แสดง modal กลางจอ — หัวข้อ "มีกระปุกออมที่เปิดอยู่" / คำอธิบายว่ามีได้แค่กระปุกเดียว / ปุ่ม **ปิด** (secondary) และ **ไปที่กระปุกออม** (primary, พาไปหน้า tracker ของกระปุกนั้น) — **ห้าม**ให้เริ่มเป้าออมที่สองได้เด็ดขาด
4. **ลงทะเบียนกระปุกออม** (`screen === 'piggyRegister'`) — ขั้น KYC ครั้งแรก (เฉพาะครั้งแรกที่เปิดบัญชีกระปุก): ช่องกรอกเลขหลังบัตรประชาชน **12 ตัวอักษร รับเฉพาะเลข 0-9 และอักษรอังกฤษพิมพ์ใหญ่ A-Z** (บล็อกภาษาไทยและสัญลักษณ์), พิมพ์แล้วแปลงเป็นตัวใหญ่อัตโนมัติ, จัดรูปแบบ `0000-0-00000-00`
5. **ตรวจสอบข้อมูล KYC** (`screen === 'piggyKyc'`) — แสดงข้อมูลโปรไฟล์แบบอ่านอย่างเดียว (ชื่อ TH/EN, วันเกิด, เลขบัตร, ที่อยู่, อาชีพ) ที่ดึงมาจากเลขบัตร; ปุ่ม "ยืนยัน" เปิด dialog ยืนยันซ้ำ ("ยืนยันข้อมูลถูกต้อง" / "ยกเลิก")
6. **ข้อกำหนดกระปุกออม** (`screen === 'piggyTerms'`) — เอกสารข้อกำหนดและเงื่อนไขบัญชี MyPiggy, ต้องเลื่อนอ่านจนสุดถึงจะกดปุ่ม "ถัดไป" ได้
7. **เปิดบัญชีกระปุกสำเร็จ** (`screen === 'piggySuccess'`) — หน้ายืนยัน "เปิดบัญชีกระปุกออมสำเร็จ", ปุ่ม "เสร็จสิ้น" → ไปหน้าตั้งเป้า
8. **ตั้งเป้าออม** (`screen === 'goalSetup'`) — "เลือกจำนวนเงินเป้าหมาย" — ปุ่มเลือกจำนวนสำเร็จรูป (1,000 / 5,000 / 10,000 / 50,000 / 100,000 / 500,000 บาท) หรือ "กำหนดเอง" (กรอกเองผ่านคีย์แพด); ปุ่ม "ยืนยัน" สร้างเป้าออม (ปิดใช้งานจนกว่าจะเลือกจำนวน)
9. **Goal Tracker** (`screen === 'goalTracker'`) — หน้าหลักของกระปุกที่เปิดอยู่: ตัวเลขยอดออมใหญ่ (`฿{saved}` จากเป้า `฿{target}`), progress bar, วันที่เริ่มออม, เลขบัญชีกระปุก; แถวสถิติสองช่อง **พร้อมฝากสลาก** (= ยอดออม) / **ซื้อสลากแล้ว** (ยอดที่ซื้อไปแล้ว); แถวปุ่มการทำงาน **ออมเงิน / ถอนเงิน / ซื้อสลาก**; **ประวัติการออม** (รายการฝาก/ซื้อ/ถอน)
   - เมื่อออมครบเป้าแล้ว จะมี **แบนเนอร์เคาท์ดาวน์ซื้ออัตโนมัติ** ปรากฏ (สไตล์ฉลอง) — ดูกฎด้านล่าง
10. **ฝากเงินเข้ากระปุก** ("ออมเงิน", `screen === 'goalDeposit'`) — คีย์แพดกรอกจำนวน ("ออมวันนี้เท่าไหร่", จำกัดไม่เกินส่วนที่เหลือถึงเป้า และไม่เกินยอดบัญชีหลักที่มี), sheet เลือกบัญชีต้นทาง, slide-to-confirm ("เลื่อนเพื่อออมเงิน") สำเร็จแล้ว: อนิเมชันฉลอง + เปิด **sheet แนะนำซื้อสลาก** (ครั้งแรกที่ยอดออมข้าม ฿1,000) หรือ **sheet ออมครบเป้า** (ถ้าครบเป้าแล้ว)
11. **Sheet แนะนำซื้อสลาก** — "ยินดีด้วย ยอดออมของคุณถึงขั้นต่ำสำหรับซื้อสลากแล้ว" + bullet ประโยชน์ + กล่อง **คำแนะนำ** สีชมพูอธิบายว่าซื้อทีเดียวก้อนใหญ่ (เทียบกับซื้อทีละน้อยหลายรอบ) จะได้เลขสลากเรียงต่อกันและมีโอกาสถูกรางวัลเลขท้าย 2/3-4 ตัวดีกว่า; ปุ่ม "ซื้อสลากตอนนี้" / checkbox ปิดคำแนะนำ "ไม่ต้องแสดงคำแนะนำนี้อีก"
12. **Sheet ออมครบเป้า** — sheet แสดงความยินดีเมื่อยอดออมครบเป้า มีกล่องคำแนะนำแบบเดียวกับข้อ 11; ปุ่มซื้อทันที หรือปิด sheet (กระปุกยังเปิดอยู่ เคาท์ดาวน์ยังทำงานต่อ — ดูกฎด้านล่าง)
13. **ถอนเงินจากกระปุก** ("ถอนเงิน", `screen === 'goalWithdraw'`) — slide-to-confirm ถอนเงิน; ถ้ามีเคาท์ดาวน์ซื้ออัตโนมัติทำงานอยู่ (ครบเป้าแล้ว) จะบังคับให้ถอนเต็มจำนวนยอดออมทั้งหมด (คีย์แพดถอนบางส่วนถูกปิดใช้งานช่วงเคาท์ดาวน์) มี dialog ยืนยันแสดงยอดสุทธิที่จะเข้าบัญชีต้นทาง, รายละเอียดค่าธรรมเนียมถ้ามี (2% หลังใช้โควตาถอนฟรี 2 ครั้ง/ปีหมด), แสดง badge จำนวนครั้งถอนฟรีที่เหลือ หรือคำเตือนสีแดงถ้าหมดโควตา
14. **ถอนเงินสำเร็จ** (`screen === 'withdrawSuccess'`) — ใบเสร็จ "ถอนเงินสำเร็จ" (ยอดรวม, ค่าธรรมเนียม, ยอดสุทธิ, วันที่); ปุ่ม "เสร็จสิ้น" พาไปหน้า Goal Tracker ถ้ากระปุกยังเปิดอยู่ หรือไปหน้าสินค้าสลากถ้ากระปุกปิดไปแล้ว
15. **หน้ากรอกจำนวนซื้อ/โอน** (`screen === 'transfer'`, ใช้ร่วมกันทั้ง "ซื้อเลย" และ "ซื้อจากกระปุก") — คีย์แพดกรอกจำนวน (ล็อกไม่เกินยอดออมในกระปุก และบังคับเป็นจำนวนเท่าของ ฿1,000 เมื่อจ่ายจากกระปุก), การ์ดสรุปสินค้า, slide-to-confirm ("เลื่อนเพื่อส่ง")
16. **ยืนยันคำสั่งซื้อ** (`screen === 'confirm'`) — สรุปคำสั่งซื้อ (บัญชีต้นทาง/ปลายทาง, สินค้า, จำนวนหน่วย) → กด "ยืนยัน" → ไปหน้า **สำเร็จ** (`screen === 'success'`) ใบเสร็จพร้อมเลขสลาก, การเผยตราสัญลักษณ์ที่ปลดล็อก, toast แจ้งได้ตั๋วสะสมคะแนน (จำกัด 20 ใบ/รอบ), และตัวเลือก "เลือกลาย" สติกเกอร์/สกินสลาก
17. **รายการล็อตที่ถือ** (ในหน้าสินค้าสลาก แท็บ "สลาก (n)") — การ์ดต่อล็อต: งวด, ช่วงเลขสลาก, วันที่ซื้อ, จำนวนเงิน, จำนวนหน่วย, badge ที่ปลดล็อก (ถ้ามี)
18. **หน้าสะสมตราสัญลักษณ์** (`screen === 'badges'` หรือใกล้เคียง) — กริดตราสัญลักษณ์แยกตามระดับความหายาก, ตัวนับปลดล็อก/ทั้งหมด, sheet รายละเอียดต่อชิ้น
19. **ประวัติเดินบัญชี** (แท็บ "รายการเดินบัญชี") — ledger การฝาก/ถอน/ซื้อของกระปุก
20. **ภาพรวมบัญชี** (`screen === 'accounts'`) — รายการบัญชีของผู้ใช้: บัญชีหลัก (หักส่วนที่ถูกกันไว้ในกระปุกที่เปิดอยู่แล้ว), บัญชีถือครองสลากดิจิทัล, และ (ถ้ามีกระปุกเปิดอยู่) บัญชีกระปุกเอง

## State Management & กฎธุรกิจ (สำคัญมาก — ต้อง implement ให้ตรงทุกข้อ)
กฎเหล่านี้ถูกแก้บั๊กซ้ำหลายรอบระหว่างรีวิวดีไซน์ — ต้อง implement ให้ตรงเป๊ะ

**การคำนวณยอดเงิน**
- ยอดเงินที่ใช้ได้ในบัญชีหลัก = `ยอดเงินในบัญชี − เงินที่ซื้อสลากตรงไปแล้ว − เงินที่กันไว้ในกระปุกที่เปิดอยู่ (ยอดออมสะสม)` เงินที่ย้ายเข้ากระปุกต้องหายไปจากยอดที่แสดงในบัญชีหลักทุกจุด (hero หน้า Home, รายการบัญชี, sheet เลือกบัญชีต้นทาง, หน้าฝากเงิน/โอน)
- การถอนเงินจากกระปุกที่มีค่าธรรมเนียม: **ยอดออมสะสมในกระปุกต้องลดลงเท่ากับจำนวนที่ขอถอนเต็มจำนวน** ไม่ใช่ยอดหลังหักค่าธรรมเนียม (เช่น ยอดออม ฿19,500 → ขอถอน ฿500 ค่าธรรมเนียม ฿10 → ผู้ใช้ได้รับ ฿490 สุทธิ แต่ยอดออมในกระปุกต้องเหลือ ฿19,000 ไม่ใช่ ฿19,010)

**มีกระปุกได้ทีละหนึ่งใบเท่านั้น**
- ผู้ใช้มีเป้าออม/กระปุกที่เปิดอยู่ได้สูงสุด 1 ใบ ในทุกสินค้ารวมกัน ถ้าพยายามเปิดใบที่สอง (กด "ออมก่อน" ที่สินค้าใดก็ตามขณะมีเป้าออมเปิดอยู่แล้ว) ให้แสดง modal "มีกระปุกออมที่เปิดอยู่" แทนการเข้าสู่ flow ตั้งเป้าใหม่

**เงื่อนไขปิดกระปุก (สำคัญ — ห้ามปิดเร็วเกินไป)**
- กระปุก/เป้าออมจะปิด (กลายเป็น `null` ปลดล็อกให้เปิดใบใหม่ได้) **เมื่อยอดออมสะสมเหลือ 0 เท่านั้น AND ต้องบรรลุเป้าหมายจริงแล้ว** (คือยอดฝากสะสม + ยอดที่ใช้ซื้อสลากไปแล้วจากกระปุกนี้ ≥ เป้าหมาย)
- ถ้ายอดออมเหลือ 0 ด้วยสาเหตุอื่น (เช่น ผู้ใช้ถอนออกหมด หรือใช้ซื้อสลากจนหมด ก่อนถึงเป้า) กระปุกยังต้อง**เปิดอยู่ต่อ**โดยมี `saved = 0` ผู้ใช้ฝากเงินต่อไปยังเป้าเดิมได้
- กฎนี้ใช้ทั้งกับการ "ซื้อสลากจากกระปุก" และการ "ถอนเงิน"

**โควตาถอนฟรี**
- แต่ละเป้าออม/กระปุกได้สิทธิ์**ถอนฟรี 2 ครั้ง/ปี** โดยนับ**แยกต่อกระปุกแต่ละใบ** (เก็บไว้ที่ตัว object ของ goal ไม่ใช่ global) — ปิดกระปุกแล้วเปิดใบใหม่ = รีเซ็ตโควตา การถอนครั้งที่ 3 เป็นต้นไปในปีนั้นเสียค่าธรรมเนียม 2%

**เคาท์ดาวน์ซื้ออัตโนมัติ**
- เมื่อยอดออมถึงเป้าหมายพอดี ให้เริ่มเคาท์ดาวน์ 24 ชั่วโมง (แสดงเป็นแบนเนอร์/ตัวจับเวลาที่หน้า Goal Tracker และหน้าสินค้าสลาก) ระหว่างเคาท์ดาวน์:
  - ผู้ใช้ยังซื้อสลากบางส่วนจากกระปุก หรือถอนบางส่วนได้; เคาท์ดาวน์ยังทำงานต่อตราบใดที่กระปุกยังมียอดออมเหลืออยู่
  - ถ้าผู้ใช้ถอนจนยอดออมเหลือ 0 ระหว่างเคาท์ดาวน์ กระปุกจะปิดและเคาท์ดาวน์/แบนเนอร์หายไปทันที (ตามกฎปิดกระปุกด้านบน เนื่องจากบรรลุเป้าแล้ว)
  - ถ้าเคาท์ดาวน์นับถึง 0 ก่อนผู้ใช้ทำอะไร ระบบจะซื้อสลากอัตโนมัติด้วย**ยอดออมคงเหลือทั้งหมด** (ไม่ปัดลงเป็นจำนวนเท่าของ ฿1,000) แล้วปิดกระปุก
- เคาท์ดาวน์ต้อง**คงอยู่ข้ามการนำทาง** — เช่น ไปหน้าซื้อ/ยืนยันแล้วกดกลับ ต้องไม่รีเซ็ตหรือล้างเคาท์ดาวน์ จะล้างได้เมื่อกระปุกปิดจริงเท่านั้น

**การตรวจสอบข้อมูลยืนยันตัวตน**
- ช่องเลขหลังบัตรประชาชนรับเฉพาะเลข 0-9 และอักษรอังกฤษพิมพ์ใหญ่ A-Z (แปลงเป็นตัวใหญ่อัตโนมัติ) สูงสุด 12 ตัวอักษร ปฏิเสธภาษาไทยและสัญลักษณ์/เครื่องหมายวรรคตอน

**เพดานการได้ตั๋วสะสม**
- ตั๋วสะสมคะแนนได้ 1 ใบต่อ ฿500 ที่ใช้ซื้อ จำกัดสูงสุด 20 ใบต่อ "รอบ" (รอบละประมาณ 1 เดือน คิดจากวันที่ 16 ของเดือน) การซื้อที่เกินเพดานแสดงตัวบอก "ครบเพดานแล้ว" แทน toast แจ้งได้ตั๋วปกติ

## Design Tokens
ห้าม hardcode ค่าเอง ใช้ `design-system/tokens/*.css` (`colors.css`, `typography.css`, `spacing.css`, `motion.css`, `fonts.css`) และ `design-system/styles.css` รวมถึง component bundle ใน `design-system/` (ปุ่ม, การ์ด, input, icon, avatar ฯลฯ) ค่าแบรนด์หลักไว้อ้างอิงเร็ว (ยึดไฟล์ token เป็นความจริง):
- สีแบรนด์แดงชมพู `#D83152` (primary/accent), สถานะกด `#9C233B`
- พื้นหลังชิพสีชมพูพาสเทล ใช้กับ badge/กล่องคำแนะนำ/การ์ดสรุปกระปุก
- ปุ่มหลัก: ทรงเม็ดยา (radius 25px), ไล่เฉด `#FA7C93 → #F14658`
- ไล่เฉด header: `#FC7C96 → #D83152`
- ไล่เฉดหมวดสลาก: `#FF8840 → #F9AD4C`
- การ์ด: พื้นขาว, radius 16px, เงานุ่มสีเทาอมฟ้า
- ฟอนต์: SF Pro Display ตลอดทั้งแอป (weight 300–700)

## Assets
- ไอคอน: ชุด SVG ของ MyMo เอง (`design-system/assets/icons/`) — tint ได้ด้วย CSS `color`/`fill: currentColor`
- ไม่มีภาพถ่ายหรือ emoji ใน flow นี้ ภาพประกอบเป็น flat SVG แบบง่าย (มาสคอตหมู, เหรียญ, เมฆ) วาดแบบ inline ใน prototype — ให้ recreate เป็น SVG component หรือขอภาพจริงจากทีมดีไซน์

## ไฟล์อ้างอิง
- `prototype-reference.html` — prototype ที่คลิกใช้งานได้จริง (เปิดตรงในเบราว์เซอร์) ยึดเป็นความจริงสำหรับคำ (ภาษาไทย), เลย์เอาต์, และ state transition ทั้งหมด (หาชื่อ method ที่อ้างถึงข้างบน)
- `design-system/` — MyMo design system: tokens, component bundle, icons, fonts
